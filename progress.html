Finding 5.1b — found by the smoothing pass, now closed. The Socket.io join-document auto-add (server.js:838) wrote role: 'editor' unconditionally, so a visitor arriving through a viewer public link was silently promoted to a persisted editor — defeating the 5.1 fix and then the 5.3 fix as well. Fix (design b): derive, do not persist. The updateOne is gone; the branch now reads doc.publicAccess.role on every join and writes nothing, with an explicit Acces refuse on the fallthrough. This matches the 5.1 REST fix, keeps the share link genuinely revocable, and drops the now-redundant collaborator re-read. Guarded by specs E1/E2/E3 plus over-block guards D12–D16 in server/__tests__/acl/socket-join-authorization.test.js (a real socket.io-client harness, not a stub). Verified as a real gate: reverting server.js to the pre-fix commit makes E1, E2, E3 and D12 fail; restoring it makes all 8 pass.
Known cost of design (b), accepted deliberately. Link visitors are no longer persisted, so a link-shared document stops appearing in a visitor's GET /api/documents list, and an offline past visitor drops out of the @mention / scene-assignee dropdowns (live presence is unaffected — both sidebars merge activeRooms). App.jsx:1285 still gates the destructive "overwrite server copy" button on collaborators.length <= 1, a counter that used to be incremented by the bug itself. Tracked in AUDIT.md §5.1b-rationale as a Phase 3 item, not a security blocker.
